AnimateHumanoid Guide

Animating a character with AnimateHumanoid

AnimateHumanoid is the component that makes a humanoid character walk, run and idle without any animation clips. There is no Animator Controller, no recorded motion and nothing to bake — every movement is calculated fresh, every frame, from a set of settings you adjust in one Inspector. Add this single component to a character and it starts moving.

This page walks through what the component is, how to add it to a character, and what each part of its Inspector controls.

A note on this page’s screenshots: the environment this guide was written in did not have access to a Unity Editor session it was safe to modify for screenshots, so this page describes the Inspector’s layout in prose and lists its controls by name and section instead of showing them. Anyone editing this page from inside the Unity Editor should add real screenshots of each section described below — that will make this guide considerably easier to follow for a first-time reader.

What it actually does

Everything about how the character moves — how fast, how the legs swing, how much the hips sway, whether the walk turns into a run — is expressed as settings: numbers and sliders, not recorded motion. Because those settings are stored as proportions of the character’s own body (a fraction of leg length, a fraction of hip width) rather than as fixed distances, one saved set of settings produces a matching look on characters of very different sizes and proportions. That is what makes the presets and the Save/Load JSON buttons useful: a “Cartoon” walk saved from one character looks like the same cartoon walk on a much taller or shorter one.

Under the hood, AnimateHumanoid is a thin wrapper around two other components it automatically adds and hides: one works out the pose for the current frame from your settings, and the other writes that pose onto the character’s bones after Unity’s own Animator and any Animation Rigging setup have already run. You never need to see or touch either of them — AnimateHumanoid is the only part of this system meant to be visible in the Inspector or referenced from your own scripts.

Requirements

Before adding the component, the character needs:

  • An Animator component with its Avatar set to Humanoid (not Generic). This is what lets the system find the character’s hips, spine, arms and legs by their standard humanoid roles, regardless of what the bones are actually named in that particular model.
  • A uniform scale on the character (the same scale value on X, Y and Z). A character scaled differently on different axes cannot be measured correctly and the system will refuse to animate it rather than produce a distorted result.
  • A skinned mesh, so the system can read the character’s true rest pose from the mesh itself.

Adding it to a character

  1. Select the character’s root GameObject — the one carrying the Animator — or, if you have already built a controller/visual hierarchy split (see the note on placement below), the visual root.
  2. Add Component ▸ AnyMotion ▸ Animate Humanoid.
  3. Unity will add two more components alongside it automatically: one that measures the character’s body (leg length, hip width, shoulder height) and one that turns settings into a pose each frame. You do not add these yourself and they do not appear as separate entries in the Inspector — AnimateHumanoid owns and hides them, presenting their settings as a single combined UI instead.
  4. Find the body-measuring component in the Inspector (it stays visible, since it is shared by other tools in this asset) and press Measure. Until a character has been measured, AnimateHumanoid shows a warning at the top of its Inspector and does nothing.
  5. Once measured, the character should immediately start animating in the Scene view if edit-mode preview is on (see Preview and Debug below), or in Play mode regardless.

If a measurement fails, the warning will say why — almost always either the Avatar is not set to Humanoid, or the character’s scale is not uniform.

Where to put it: the hierarchy matters

AnimateHumanoid writes to the character’s bones every frame. If something else — a CharacterController-driven movement script, for example — is also writing to the same transform each frame, the two writes fight each other and produce jitter or drift. The safe pattern is a two-level hierarchy: an outer object that your movement code moves around the world, and an inner “visual root” object, parented under it, that carries the Animator and this component. Movement code only ever touches the outer object; AnimateHumanoid only ever touches the inner one.

The menu command Tools ▸ AnyMotion ▸ Setup Third Person Character builds this hierarchy correctly and adds AnimateHumanoid to it, which is the fastest way to get a working example if you are setting one up from scratch.

The Inspector, section by section

The Inspector is organised top-to-bottom by what you are actually deciding, not by which internal component a setting happens to live on. Every field carries its own tooltip written for someone with no animation background — hover over anything you are unsure about. The sections below summarise what each one is for and when you would open it.

Presets

The fastest way to see the system doing something. Five buttons apply a complete, ready-made set of settings: Neutral (an ordinary upright walk — the starting point the others change), Cartoon (exaggerated, bouncy, long high steps), Horror (slow, hunched, uneven, with joints that snap rather than ease), Limp (one leg noticeably shorter, lower and stiffer than the other), and Run (a running gait with an airborne moment where both feet leave the ground). Below the presets, Load JSON… and Save JSON… read and write a settings file you can share with someone else or check into version control, and Reset All returns every setting to its default without touching scene references such as look-at or hand targets.

Movement

How fast the character moves, how a walk turns into a run, and what happens when it stops. This includes the overall Animation Weight (0 keeps the character in its unanimated rest pose, 1 is full animation — useful for fading the system in or out), the core timing settings (steps per second, or a move speed the system converts into steps per second for you), the run blend settings that describe what changes as speed rises into a run (duty factor, step length, lean, and an overall “how energetic” multiplier, each blended in gradually rather than snapped), and the idle settings that describe how the character settles when it stops moving — how long the transition to standing still takes, and the small breathing and weight-shifting motion that keeps a standing character looking alive instead of frozen.

Steps and Ground

Where each foot lands, and how the character reacts to ground that isn’t flat. The footstep settings shape a single step: how far it reaches, how high it lifts, how far apart the feet are placed, and the angle the foot lands and leaves at. The ground settings and the ground probe fields just below them (which layers count as “ground”, and how far up and down the system looks for it) work together: the ground settings describe how a foot should react to uneven terrain, and the probe fields tell it physically where to look for that terrain in your scene — which is why they are grouped together here even though they used to live in two separate Inspectors. Further down, slope settings control how far the hips tilt to lean into a slope and how much a step shortens rather than lowering the hips when the ground is steep, and knee settings control knee-bend angles directly — these only take effect if the project is using an older internal driver mode; with the default mode the knee angle follows automatically from where the foot is placed, so raising Step Height under Footstep is the normal way to change how high the leg lifts.

Body and Style

The part of the character that decides what it reads as, rather than where it goes. Pelvis settings cover how the hips rise and fall, sway side to side, surge forward and back, and turn and tip through the cycle — this is the single biggest contributor to a character’s overall silhouette while moving. Torso covers lean, sideways bend and twist of the spine and chest. Arms covers how far the arms swing, how they’re held, elbow bend, and — importantly — how far a hand reaches towards an assigned hand target (the two “Left/Right Hand Target” fields just below, for pointing a hand at a specific world object such as something to carry or grab) instead of following the ordinary swing, along with three limits on how far up, across and behind the body a hand may reach before the system gives up and lets the arm swing normally instead. Head covers the head’s own bob, turn and tilt as the character walks, and how much it counter-turns to keep facing forward rather than swinging with the torso. Look At, together with the Look At Target field below it, turns the head, neck and chest towards an assigned object — assign a Transform there (for example, whatever the character should be watching) and adjust how much of the turn each of the three body parts contributes, and how far and how fast they’re allowed to turn.

Variation

What stops the animation reading as an exact, obviously looping repeat, and what makes two characters with the same settings move a little differently from each other. Irregularity mixes in a small amount of slow random drift and/or fast jitter on top of every movement, and a seed value so a crowd of otherwise-identical characters doesn’t move in perfect unison. Asymmetry makes one specific leg move differently from the other — shorter, lower or stiffer-kneed — which is the general mechanism behind the Limp preset above and is also how you would build a similar lopsided or injured gait of your own.

Preview and Debug

Controls for watching the animation while you edit — none of these affect a built game. Preview In Edit Mode runs the animation continuously in the Scene view without pressing Play. Draw Gizmos and Draw Trails turn on debug visualisation. While preview is off, a Scrub Cycle slider lets you step through exactly one gait cycle by hand to inspect a specific pose; it is hidden while preview is running, because the preview would immediately overwrite anything the slider set. Two buttons below that: Restart Cycle puts both feet back at the start of the cycle, and Reset Pose re-reads the character’s rest pose from its mesh and reattaches to its bones from scratch — useful if a script recompile left the character looking wrong.

Advanced

Collapsed by default, and correct as shipped for most projects — open it only if you have a specific reason to. It holds the internal driver space selection and update rate, read-only references to the component’s own dependencies (filled in automatically, shown here only for troubleshooting), a Re-attach To Bones button for after you change the Avatar or replace the mesh, and a Driver space comparison foldout that is development/reference information about the system’s internal techniques rather than something a typical project needs to touch.

Live Stats

A foldout at the very bottom of the Inspector — deliberately last, since its contents change every frame and anything below a constantly-changing readout would visually shift around as you work. Expand it to see what the animation is doing right now: current cadence and step length, whether each foot currently reads as on the ground or in the air, hip offset and rotation, and knee/thigh angles. This is the fastest way to confirm a character controller is actually feeding in the speed you expect, and it will warn you if a foot is being asked to reach further than the character’s leg is physically long — a sign to reduce Step Length or Stance Width rather than a bug.

Controlling it from your own scripts

AnimateHumanoid exposes a small public surface for game code, all of it safe to read and write at runtime:

  • Weight — fade the animation in or out (0 to 1).
  • MoveSpeed / MoveDirection — write these from your movement code each frame if you have turned off automatic speed measurement, or if facing and travel direction can differ (for example, strafing). MoveDirection is in degrees relative to the way the character is facing: 0 is straight ahead, 90 is sideways to the right, 180 is walking backwards.
  • LookAtTarget — assign or clear a Transform for the head/neck/chest to turn towards; safe to reassign every frame.
  • LeftHandTarget / RightHandTarget — assign a Transform for a hand to reach towards, for example a point on an object being carried.
  • Parameters, Pose, Phase — read or edit the full settings, the current computed pose, and the current position in the gait cycle (0 to 1, one cycle is two steps).
  • IsReady / IsBound — check whether the character has been measured and attached to its bones before relying on it.
  • FootMissedGround — an event raised when a foot’s downward ground probe finds nothing to stand on (for example, swinging out over a ledge). The animation already handles this gracefully on its own by keeping the foot within a normal stride; this event exists for game code that wants to react to it separately, such as triggering a stumble or a ragdoll handoff. This event’s exact payload shape is still provisional and may change before release.
